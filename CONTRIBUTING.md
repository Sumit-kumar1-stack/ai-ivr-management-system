# Contributing

Thanks for your interest in improving this project.

## How to contribute

1. Fork the repository or create a feature branch.
2. Keep changes focused and easy to review.
3. Follow the existing project structure, naming, and coding conventions.
4. Add or update tests when behavior changes.
5. Update documentation when setup, APIs, configuration, architecture, or user-facing behavior changes.
6. Run the relevant lint, type-check, test, and build commands described in the repository before opening a pull request.
7. Open a pull request with a clear summary of the problem, the solution, and how you validated it.

## Pull request guidance

A good pull request should:

- explain **why** the change is needed;
- avoid unrelated refactors;
- call out migrations, configuration changes, or breaking changes;
- include screenshots or recordings for meaningful UI changes;
- avoid committing secrets, credentials, production data, generated dependency folders, or local environment files.

## Issues

When reporting a bug, include enough information to reproduce it: expected behavior, actual behavior, environment details, relevant logs, and minimal reproduction steps when possible.

For security-sensitive findings, follow `SECURITY.md` instead of opening a public issue.
