# Security Policy

Security reports are welcome and should be handled responsibly.

## Reporting a vulnerability

Please **do not open a public issue containing exploit details, credentials, tokens, personal data, or other sensitive information**.

Instead, contact the repository maintainer privately through the GitHub account associated with this repository. If GitHub private vulnerability reporting is enabled for the repository, prefer that channel.

Include:

- a concise description of the issue;
- affected component or endpoint;
- reproduction steps or a proof of concept;
- potential impact;
- any suggested mitigation, if known.

Please remove or redact real credentials, customer data, health data, identity data, payment information, and other sensitive records from reports.

## Scope

Security-sensitive areas can include authentication, authorization, tenant isolation, secrets handling, input validation, dependency vulnerabilities, data exposure, unsafe logging, file handling, webhooks, external integrations, and infrastructure configuration.

## Disclosure

Please allow reasonable time for investigation and remediation before public disclosure.
